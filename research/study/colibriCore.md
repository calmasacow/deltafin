# colibri deep-read: core engine analysis (repo: research/colibri)

Engine = one translation unit `c/colibri.c` (6,751 lines; README still calls it `glm.c`) + small headers (`st.h`, `quant.h`, `tier.h`, `uring.h`, `compat.h`, `kv_persist.h`, `fse_coli.h`). No BLAS, no Accelerate, no Python at runtime. `c/olmoe.c` is a separate, simpler OLMoE engine (the "Stage A" prototype: f32 dense + int8 LRU expert cache, olmoe.c:1-80) — the real machinery is all in colibri.c.

## 1. Memory hierarchy / tiers / LRU

Tiers, hottest→coldest: **(a) VRAM expert tier** (CUDA only; `pin_load` uploads a heat-ranked prefix until `CUDA_EXPERT_GB` budget, colibri.c:5962-6061; optionally frees host copy `CUDA_RELEASE_HOST`), **(b) pinned RAM hot-store** `m->pin[layer]` (`ESlot` arrays, never evicted by the LRU; loaded at startup from persisted usage stats `.coli_usage` via `pin_load`, colibri.c:5925; mlock'd by `pin_wire`, colibri.c:5773 — mlock defaults ON on macOS, colibri.c:5718-5724), **(c) per-layer LRU cache** `m->ecache[layer]` with count `ecn[layer]` and global cap `ecap` (Model struct colibri.c:190), **(d) OS page cache as free L2** (default `DROP=0` leaves expert pages cached, colibri.c:565-567), **(e) disk**.

Data structures: `ESlot { int eid; QT g,u,d; uint8_t *slab; float *fslab; caps; uint64_t used; arena ptrs }` (colibri.c:156-162). The three expert matrices are *views into one slab* (zero copies). `ws[64]` is the per-block working set of miss slots reused across layers (colibri.c:193). Bookkeeping arrays per layer: `eusage` (persistent counters → `.coli_usage`, saved every turn, colibri.c:5684-5689), `eheat` (recent heat for promotion/demotion), `elast`/`eaccess_clock` (recency for LFRU) (colibri.c:195-197).

Eviction: the **main LRU is pure LRU** — on block end, missed experts in `ws[]` are swapped into `ecache`; when full, victim = min `used` (a global monotonically increasing `eclock`), colibri.c:3488-3494. Hits bump `used` (colibri.c:3035). **Speculative (PILOT) inserts use an LFRU guard**: `tier_lfru_score = (heat<<8)|recency` (tier.h:30-33); a speculation may not evict a victim with ≥2 demand accesses unless it beats it by 25%+4-freq hysteresis (colibri.c:3636-3651, fix #490). **Pin-tier adaptation** (`REPIN=n`, opt-in): every n emitted tokens, `repin_pick`/`tier_pick_lfru` swaps the coldest pinned expert for the hottest non-resident one with the same hysteresis, then halves all heat (`tier_decay`) (colibri.c:5137-5228, tier.h:35-58). `cap_for_ram` (colibri.c:6126-6214) computes `ecap` from a RAM budget (auto = 88% of MemAvailable at boot) with explicit slack: 1.2 GB overhead + 2.5 GB page-cache reserve + 64×expert_bytes working set + KV pool + k/v scratch; it auto-raises cap on big-RAM hosts and refuses to start if even cap=1 exceeds physical RAM. An **RSS guard** (#403, colibri.c:5092-5135) shrinks `ecap` live if measured RSS crosses the budget.

## 2. Expert streaming I/O path

**Default is `pread`, not mmap** (st.h:1-6 explains: mmap kept the whole model in RSS). Container: normal **safetensors shards** where each expert tensor is pre-quantized `U8` bytes plus a companion f32 scale tensor named `<tensor>.qs`. `st_init_multi` indexes all `model-*.safetensors` with an open-addressing hash of ~120k tensor names (st.h:248-360). In the pre-quantized container, **gate/up/down of one expert are laid out adjacent in the file**, so `expert_load_impl` detects contiguity and issues **ONE coalescing pread of ~19 MB** into the slot slab (colibri.c:1590-1616); non-contiguous fallback = 3 preads sorted by offset; scales = 3 small buffered preads. Load is timed into `g_edisk_ns` (colibri.c:1660-1671).

- **O_DIRECT** (`DIRECT=1`): a lazily-opened "twin" fd per file; Linux `O_DIRECT`, **macOS = `F_NOCACHE` via `compat_open_direct`** (compat.h:39-48), Windows NO_BUFFERING. Reads are aligned: base = offset & ~4095, length rounded up to 4 KiB (colibri.c:1598-1608). Scales always stay buffered. On the M5 Max Metal run DIRECT=1 was ~2× faster and required for zero-copy GPU slabs (docs/METAL-M5MAX-PERF-REPORT.md).
- **mmap mode** (`COLI_MMAP=1`): whole-file `MAP_SHARED` maps (`map_of_fd`, colibri.c:1307-1326); QT pointers become zero-copy views; `madvise(WILLNEED)` + explicit page-touch pre-fault so a GPU never demand-faults file pages (colibri.c:1495-1516); pinned set mlock'd via `qt_wire_mmap`.
- **io_uring** (`uring.h`): hand-rolled ring (no liburing), `IORING_OP_READ` with `IOSQE_ASYNC` forced so cold buffered reads go to io-wq workers instead of executing inline (uring.h:99-104); one submit syscall per expert batch, CQE reap on demand (colibri.c:1673-1857). **Strictly `#ifdef __linux__`** (uring.h:7, colibri.c:50-52); on macOS `URING=1` exits with "URING=1 is supported only on Linux" (colibri.c:~6448). The macOS/portable async path is the **PIPE pthread pool**: 8 (cap 16) I/O worker threads, lock-free generation-tagged cursor `(gen<<8)|index` with CAS job grab, per-slot `ready[]` flags; main thread spins `sched_yield` on `pipe_wait` (or condvar with `COLI_PIPE_BLOCK=1`) and does all matmuls itself (colibri.c:1859-2009). PIPE defaults OFF except Windows.
- **Prefetch hints**: `posix_fadvise(WILLNEED)`; on macOS shimmed to `fcntl(F_RDADVISE)` (compat.h:14-37); `DONTNEED` is a **no-op on macOS**. `moe()` also issues WILLNEED readahead for the *next block of 64 unique experts* while computing the current one (colibri.c:3113-3124).

`cfse_pack.c` is NOT the expert layout tool — it's a whole-shard **entropy-coding converter**: per-tensor rANS ("CFS1" streams, fse_coli.h) inside an otherwise normal safetensors file, `__metadata__.cfse=1`. The coder is order-0 nibble rANS, 2 interleaved states, 12-bit freqs, ~**1.37× compression on int4 weights** (measured; int4 weights are statistically white so order-0 is optimal — fse_coli.h:1-24), with bounds-checked decode and a state-seal integrity check. It's a local experiment (not integrated in the hot read path).

## 3. Router-lookahead prefetch (PILOT)

`pilot_prefetch` (colibri.c:3847-3909) runs **inside the forward pass** after layer L's attention: it rms-norms L's post-attention hidden state with **layer L+1's `post_ln`**, runs L+1's router matmul + sigmoid + bias, takes top-`PILOT_K` (default 8; 6 under PILOT_REAL), skips already-resident experts (residency scan under `g_pilot_mx`), and enqueues (layer,eid) on a **lock-free 4096-entry SPSC ring** (`pilot_q`, colibri.c:3618-3620). A **dedicated pthread** (`pilot_worker`, colibri.c:3758-3774; created lazily) drains the ring: with `PILOT=1` it issues WILLNEED readahead (`expert_prefetch`); with `PILOT_REAL=1` it does **real `expert_load`s into the future layer's LRU** (`pilot_realload`, colibri.c:3624-3672) — slot chosen under mutex, published only after a successful load (eid=-1 hides it while loading; URING variant reserves with eid=-(eid+2)); non-fatal on error. Measured recall: **71.6% one layer ahead vs 41.3% previous-token routing** (comment colibri.c:3606-3612, README). `PILOT_TWO` improves recall +2.3% by approximating layer L's MoE output with just the resident shared expert before running L+1's router (colibri.c:3853-3877). Safety: `moe()` takes ownership of the current layer (`g_cur_moe_layer`) and waits for in-flight pilot loads on it (`g_pilot_inflight[]` + condvar barrier, colibri.c:2719-2728); the worker drops predictions for layers ≤ current. Hints are issued from the thread because inline `fadvise` submit blocked ~0.5 ms/call (measured +92 s / 48 tokens, colibri.c:3613-3617). A separate **COUPLE** mechanism (`.coli_pairs` offline co-occurrence stats) prefetches conditioned pairs 1-2 layers ahead (colibri.c:3777-3846). `LOOKA=1` measures predictability without acting.

## 4. Dual-SSD

Two *complete or partial byte-identical copies*. `st_mirror_init` (st.h:134-178) accepts a mirror file only if size AND safetensors header are byte-identical (so data_offsets match). Routing: `expert_route(layer,eid)` = deterministic 32-bit hash → mirror if `(h&255) < g_mir_share` where share = 256·wm/(wp+wm) from `COLI_DISK_WEIGHTS` or a startup bandwidth probe (8 parallel 19 MB O_DIRECT preads per drive, `mirror_probe_bw` colibri.c:5809-5835). Determinism is load-bearing: prefetch WILLNEED and the demand pread must warm/hit the same fd, and no expert is cached twice (colibri.c:1340-1349). Read errors fall back to the primary (mir_pread, colibri.c:1363-1377); mirror is never written. A separate **SPLIT** mode (`st_init_multi` extra_dirs, st.h:242-272) spreads shards across N drives with *no duplication* (capacity aggregation, per-shard placement).

## 5. Speculative decoding (MTP)

`spec_decode` (colibri.c:4536-4615). Draft sources in priority order: (1) grammar-forced spans (GBNF/JSON-schema, ~free acceptance on constrained output), (2) **native MTP head** if present, (3) n-gram prompt-lookup. `mtp_draft` (colibri.c:4347-4383) implements the DeepSeek-V3 chain: emb(tok)→`enorm`; previous hidden → `final_norm` then `hnorm`; concat [emb;h] → `eh_proj` [2D→D]; one full transformer layer `mtpL` (index n_layers, own KV rows) → `mtp_norm` → shared `lm_head` argmax; iterated G times feeding its own output. Verification: batch `step_all` of S=1+G through the main model; greedy accept while argmax matches; with temperature, **Leviathan rejection sampling** (accept draft with prob p(draft); on reject resample from p with the draft token banned) so output distribution is exactly p (colibri.c:4592-4601). `mtp_absorb` (colibri.c:4387-4408) back-fills the MTP layer's KV with *verified* (emb(tok@p+1), true hidden@p) pairs as one batched layer pass. Hard-won rules: **MTP head must be int8** (int4 → 0–4% acceptance, #8); `SPEC_PIN=1` pins draft+verify to the same kernel family so both compute the same function (#163, colibri.c:257-259, 4542-4546); adaptive guard pauses drafts for 256 tokens when acceptance <10% over 24 proposals (colibri.c:4551-4576). Payoff 2.2–2.8 tokens/forward when cache is warm (README).

## 6. Compressed KV (576 vs 32768)

This is **MLA latent KV** exactly: per token per layer store only the rms-normed kv-LoRA latent `Lc` [kv_lora=512] and the roped shared k_rot `Rc` [qk_rope=64] → **576 f32/token/layer** vs materializing H·(qk_nope+qk_rope+v_head) = 64·(192+64+256) = 32768 (Model comment colibri.c:184-187; write path colibri.c:2403-2419: `kv_a` projection → split, rmsnorm latent via `kv_a_ln`, rope k_rot). k_nope and V are reconstructed on the fly with `kv_b`; at decode (S≤4, `ABSORB` auto) the **absorption path** folds `kv_b` into the query/output via per-row dequant axpy (`qt_addrow`/`qt_matvec_rows`, colibri.c:2065-2138) so nothing is materialized. GLM-5.2's DSA "lightning indexer" (top-`index_topk` key selection with a small per-layer indexer cache `Ic`) is implemented alongside (colibri.c:2420-2460). KV persists to `.coli_kv` (kv_persist.h): append-only records [tok i32][Lc+Rc all layers][Ic], `nrec` written last for crash safety, ~182 KB/token; conversations reopen warm with zero re-prefill.

## 7. Quantization

Formats in `QT.fmt` (colibri.c:92-128): 0=f32, 1=int8 per-row scale, 2=int4 per-row, 3=int2, **4=int4 grouped (gs=64/128, f32 scale per group — the recommended gs64 container)**, 5=int3-g64 (3.5 bpw effective: 2-bit low plane + 1-bit high plane + f32/group scale), **6=E8/IQ3 lattice (98 B per 256 weights = 3.0625 bpw**, grid indices + parity signs + sub-scales + fp16 super-scale, requires a rotation `e8_rot_rows` of activations; quant.h:840+). On disk = the same packed bytes (safetensors U8 + `.qs` f32 scales); **in memory = identical packed form, dequantized on use** — no dequant-to-f32 blowup. Format inferred per tensor from byte counts (`qt_resolve_fmt`/`detect_group_size`, colibri.c:960-1010). Dense resident parts (attention, shared experts, embed, lm_head) int4; norms/router/bias f32 ("small and sensitive", colibri.c:10-13); MTP head int8. Two compute paths: exact (f32 activations × dequantized weights, FMA) and **IDOT** (activations quantized per-row to int8 via `qrow_i8`, integer dot `dot_i8i8`/`dot_i4i8`); attention projections force the exact path (`allow_idot=0`) because IDOT costs +0.117 nat/token there ≈ +12% ppl (colibri.c:522-528).

## 8. CPU compute

Threading: **OpenMP** `parallel for` over output rows inside every matmul (quant.h:99+); the main thread runs all matmuls (GPU dispatch checks `!omp_in_parallel()`); I/O on the PIPE pthread pool or an OMP `parallel for schedule(dynamic,1)` blocking load (colibri.c:3100-3112); PILOT on its own pthread. Startup seeds `OMP_WAIT_POLICY=active`, `GOMP_SPINCOUNT=200000`, `KMP_BLOCKTIME=200`, `OMP_PROC_BIND=close` and re-execs once (Linux/FreeBSD) — skipped entirely when `COLI_METAL`/`COLI_CUDA` env set (colibri.c:6263-6329). `XEXP=1` collapses the per-expert fork/join cadence into ONE parallel region across the whole block (+11.6% on a 48-core box; opt-in, neutral on small cores; colibri.c:3232-3298). SIMD (quant.h): AVX2 / AVX-512(+VNNI) / AVX-VNNI / **NEON** (baseline fmadd; `__ARM_FEATURE_DOTPROD` sdot with 4 independent accumulators; `__ARM_FEATURE_MATMUL_INT8` smmla 2×2-tile kernels for S≥2 — **not available on M1**, which lacks i8mm) / POWER VSX. With DOTPROD, int4-IDOT engages even at S=1 (`g_i4s=1`, quant.h:368-380). GEMM approach: it's all row-parallel GEMV/GEMM by dot products — no blocked/packed GEMM, **no BLAS/Accelerate anywhere** (Makefile confirms; arm64 build has no -march, NEON is baseline). Fused gate+up kernels read activations once (`matmul_i4_pair`, `matmul_i4_grouped_pair`).

## 9. GLM-specific vs generic (port cost to Kimi K3)

**Generic/reusable**: the whole storage stack (st.h, hash index, mirror/split), ESlot/LRU/pin/heat/LFRU tiering + `.coli_usage` learning cache, cap_for_ram/RSS-guard, PIPE/URING/PILOT/COUPLE machinery, all quant kernels + IDOT, batch-union MoE driver, spec-decode verifier, telemetry, cfse. tier.h and decode_batch.h are deliberately model-independent seams.
**GLM-hardwired**: (a) tensor name templates `model.layers.%d.mlp.experts.%d.{gate,up,down}_proj.weight` + `.qs` (colibri.c:1451-1453, also in uring_load_add, pin_arena_bind, expert_prefetch); (b) config keys and hard `n_group==1` requirement (load_cfg colibri.c:870-957); (c) sigmoid router + bias "noaux_tc" + `routed_scaling_factor` + norm_topk (moe FASE A colibri.c:2789-2918); (d) the entire attention: MLA q/kv-LoRA, absorption, DSA indexer, and KVState layout (Lc/Rc/Ic) — all MLA-specific; (e) MTP chain names/order; (f) Metal fused decode attention is **gated on literal GLM-5.2 dims** (D==6144, H==64, q_lora==2048, kv_lora==512, qk_nope==192, qk_rope==64, vh==256, int4 kv_b — colibri.c:2344-2346).
For **Kimi K3**: the MoE/streaming/caching side is a config+naming port (K2-family routers are sigmoid top-k, very close). The hard part is **Kimi Delta Attention**: KDA's linear/delta-rule layers have a *fixed-size recurrent state*, not a growing KV — colibri's KVState, kv_persist format, attention_rows, absorption and the Metal attention kernel all need replacement for those layers (any K2-style MLA global layers could reuse the existing path). Kimi checkpoints also usually store experts *stacked* in fused [E,...] tensors — colibri already has a slice reader for that (`st_read_slice_f32`, st.h:461-477) but the fast path (one contiguous pread per expert + `.qs`) requires re-packing via the converter, which is where the on-disk adjacency is created (tools/, per README "each expert's three matrices stored adjacent").

## 10. Apple-Silicon-suboptimal / Linux-first

- io_uring is Linux-only; macOS gets the pthread PIPE pool whose default wait is a **sched_yield spin** on the main thread (colibri.c:2008) — on a 10-core M1 Max this fights the OMP team; `COLI_PIPE_BLOCK=1` exists.
- The OMP **active-spin auto-tuning is a measured −39% trap with Metal on Apple Silicon** (CPU spin steals the shared SoC power budget and the GPU downclocks: attention kernel 76 s→223 s; docs/METAL-M5MAX-PERF-REPORT.md). Winner recipe there: `COLI_METAL=1 DIRECT=1 COLI_NO_OMP_TUNE=1 PIPE=1 PIPE_WORKERS=8` → 2.24 tok/s GLM-5.2 on M5 Max/128 GB. The report explicitly recommends passive OMP wait as default on Metal builds — not yet the default.
- `posix_fadvise` shim: WILLNEED→`F_RDADVISE` ok, **DONTNEED→no-op** (compat.h:16-19) so `DROP=1` does nothing; page-cache pressure is left to XNU.
- O_DIRECT→`F_NOCACHE` twin fd (no alignment constraint, semantics differ from Linux O_DIRECT).
- NUMA interleave, sched_setaffinity, /proc/self/exe re-exec: Linux-only (no-ops/absent on macOS).
- Metal backend is opt-in + "experimental": ~5 ms submit latency forces heavy batching; fused attention only for exact GLM dims and S≤4; GEMM offload only for S≥16 rows; `useResource:` residency stall at large LRU caps (25.9 s→3.9 s only in the experimental E4/E5 branches — SUMMARY.md documents `MTLResidencySet` (macOS 15+) as the fix, env `COLI_METAL_RESSET=1`, not yet mainlined); slabs must be 16 KiB-aligned for `newBufferWithBytesNoCopy` (colibri.c:1528-1535).
- **No Accelerate/AMX use at all** — dense GEMV runs on NEON only; Apple's AMX units (reachable only through Accelerate) are left idle.
- MLOCK defaults ON on macOS (good); mem available via `host_statistics64` free+inactive+purgeable (colibri.c:6080-6087). M5 report: crossing into macOS memory compression is a double penalty (compressor CPU + SoC power) — budget must stay well under physical RAM.
- Run-to-run non-determinism under PIPE/Metal parallel reductions (benign; documented in the M5 report).

## KEY FACTS
- colibri runs GLM-5.2 744B MoE in ~25 GB RAM: dense part (~17B params) resident at int4 (~9.9 GB), 19,456 routed experts (75 sparse layers x 256 + MTP) of ~19 MB each at int4 (~370 GB) streamed from disk (README.md:63-79)
- Expert on-disk layout: pre-quantized safetensors (U8 payload + companion f32 '<name>.qs' scale tensor); gate/up/down of one expert are file-adjacent so a miss costs ONE ~19 MB pread into a reusable slab; QT views are zero-copy into the slab (colibri.c:1590-1656)
- cfse_pack.c is a shard-level rANS entropy coder (order-0 on nibbles, 2 interleaved states): measured 1.37x lossless compression on int4 expert weights because int4 weights are statistically white (fse_coli.h:1-24) - not integrated into the hot read path
- Eviction: main per-layer expert cache is pure LRU on a global access clock (colibri.c:3488-3494); pilot speculative inserts use LFRU score (heat<<8|recency) with a 25%+4-frequency hysteresis guard protecting warm demand experts (tier.h:30-53, colibri.c:3636-3651); pinned hot-store is never LRU-evicted and adapts only via opt-in REPIN passes
- PILOT router-lookahead: run layer L+1's router on L's post-attention state; measured 71.6% top-K recall one layer ahead vs 41.3% from previous-token routing; +2.3% recall with two-step (add shared-expert output first); loads run on a dedicated pthread via a lock-free 4096-slot ring (colibri.c:3606-3909)
- io_uring is compiled only under #ifdef __linux__; on macOS URING=1 hard-errors and the async path is a pthread pool (PIPE=1, default 8 workers, lock-free generation-tagged CAS cursor, main thread spins sched_yield in pipe_wait unless COLI_PIPE_BLOCK=1) (uring.h:7, colibri.c:1859-2009)
- macOS I/O shims: posix_fadvise WILLNEED -> fcntl(F_RDADVISE), DONTNEED -> no-op; O_DIRECT -> F_NOCACHE twin fd with no alignment constraints (compat.h:14-48); DIRECT=1 measured ~2x decode on M5 Max Metal and required for zero-copy GPU slab feeding
- Dual-SSD: byte-identical mirror validated per file (size+header); expert->drive via deterministic hash of (layer,eid) weighted by measured/declared bandwidth out of 256; prefetch and demand read deterministically hit the same drive; read errors fall back to primary; separate SPLIT mode spreads shards across drives without duplication (st.h:134-178, colibri.c:1328-1377)
- Compressed KV = MLA latent: 512 (kv_lora, rms-normed) + 64 (qk_rope, roped) = 576 f32/token/layer vs 64 heads x (192 qk_nope + 64 rope + 256 v) = 32768; k_nope/V reconstructed via kv_b, decode S<=4 uses absorption (no materialization); persisted crash-safe to .coli_kv at ~182 KB/token (colibri.c:184-187, 2403-2419, kv_persist.h)
- MTP speculative decoding: DeepSeek-V3-style chain (enorm/hnorm -> eh_proj -> one extra transformer layer -> shared lm_head), batch verify via step_all, Leviathan rejection sampling under temperature; MTP head MUST be int8 (int4 collapses acceptance to 0-4%, issue #8); SPEC_PIN pins draft+verify to one kernel family; 2.2-2.8 tokens/forward when cache warm (colibri.c:4347-4615)
- Quant formats fmt=0..6: int8/int4 per-row, int4-grouped gs64 (recommended container), int3-g64 (3.5 bpw), E8/IQ3 lattice 3.0625 bpw (98 B per 256 weights, needs activation rotation); on-disk bytes == in-RAM bytes, dequant-on-use; IDOT int8-activation kernels everywhere except attention projections (+12% ppl there) (quant.h, colibri.c:92-128, 522-561)
- CPU compute: OpenMP row-parallel GEMV dot kernels, no BLAS/Accelerate/AMX; NEON paths use sdot (DOTPROD) with 4 accumulators and i8mm smmla 2x2 tiles for S>=2 - M1 Max has DOTPROD but NOT i8mm, so the tiled int8 kernels are unavailable there
- Apple Silicon trap: the engine's default OMP active-spin tuning cost -39% with Metal on M5 Max (CPU spin steals shared SoC power, GPU attention kernel 76s->223s); winning recipe COLI_METAL=1 DIRECT=1 COLI_NO_OMP_TUNE=1 PIPE=1 PIPE_WORKERS=8 gave 2.24 tok/s for GLM-5.2 744B on M5 Max 128 GB (docs/METAL-M5MAX-PERF-REPORT.md)
- Metal backend (opt-in, experimental): batched routed-expert SwiGLU zero-copy from 16 KiB-aligned RAM slabs, fused MLA decode attention (S<=4, hardcoded to GLM-5.2 dims D=6144/H=64/kv_lora=512), prefill GEMM for S>=16; resident-expert GPU work submitted BEFORE miss preads so I/O overlaps GPU compute; ~5 ms submit latency forces batching; MTLResidencySet fix for the useResource stall (25.9s->3.9s) exists only on experiment branches (SUMMARY.md, backend_metal.mm, colibri.c:2344-2366, 3040-3158)
- GLM-hardwiring is narrow: tensor-name templates, config keys (requires n_group==1), sigmoid+bias router semantics, MLA/DSA attention, MTP chain, and the Metal attention kernel's literal dims; the storage/caching/prefetch/spec machinery is model-agnostic - Kimi support is explicitly on the roadmap (README.md:294-297)
- Memory budget math (cap_for_ram): budget = 88% of boot MemAvailable; slack = 1.2 GB overhead + 2.5 GB page-cache reserve (measured: starving it drops buffered reads 800->180 MB/s) + 64 x expert_bytes working set + KV pool; refuses to start if projected peak exceeds physical RAM (colibri.c:6126-6214)
- Learning cache: per-expert usage counters persisted to .coli_usage every turn; startup AUTOPIN sorts by count and pins as many experts as the RAM budget allows (OMP-parallel load, mlock'd - mlock defaults ON on macOS) (colibri.c:5925-6073, 5717-5724)
- Cold decode on GLM-5.2 is disk-bound at ~11 GB/token streamed; measured floors: 0.05-0.1 tok/s on a 25 GB box, ~1.8 tok/s warm on 128 GB CPU-only, 2.06-2.24 tok/s on M5 Max Metal with 46.9 GB pin, 5.8-6.8 tok/s on 6x RTX 5090 full residency (README.md:181-201)
- Kimi K3 sizing on the M1 Max: 2.8T params at int4-gs64 (~4.5 bpw incl scales) is ~1.57 TB and does NOT fit the ~1.2 TB free NVMe; E8/IQ3 3.0625 bpw is ~1.07 TB and fits - sub-4-bit expert container is mandatory, and there is no room for a second local copy of the model

## IMPROVEMENT IDEAS
- Ship the experts in the E8/IQ3 fmt=6 container (3.0625 bpw, 98 B/256 weights, quant.h): the only in-tree format that fits 2.8T params in ~1.07 TB on the 1.2 TB free NVMe; keep the MTP head int8 (issue #8) and norms/router f32. Optionally layer the cfse rANS coder (1.37x measured on int4) on the cold tier with decompress-on-load in the PIPE workers - decode is disk-bound, so trading E-core cycles for ~27% fewer disk bytes likely wins on the M1 Max's ~5 GB/s internal SSD; benchmark the nibble-rANS decode throughput per core first
- Adopt the M5 Max Metal recipe as defaults on macOS: COLI_METAL=1 + passive OMP wait (never the active-spin re-exec - it cost -39% by throttling the GPU) + PIPE=1 with ~4-6 workers (M1 Max has only 8P+2E cores) + DIRECT=1 (F_NOCACHE, ~2x measured and required for zero-copy GPU slabs); pin PIPE/PILOT threads to E-cores via QoS so the P-cores/GPU keep the power budget
- Mainline the MTLResidencySet path (SUMMARY.md E5 design, COLI_METAL_RESSET=1, macOS 15+): the per-command-buffer useResource loop caused a 25.9s->3.9s-scale GPU stall at large LRU caps; on a 64 GB M1 Max the LRU will hold thousands of slabs, so this is first-order
- Exploit Kimi Delta Attention instead of porting MLA: KDA linear/delta layers keep a fixed-size recurrent state per layer, so the KV pool term in cap_for_ram shrinks to ~zero and long contexts cost no expert-cache RAM - implement the delta-rule scan on CPU (state is tiny), reuse colibri's MLA absorption path only for K3's periodic full-attention layers, and persist the recurrent state (a few MB) instead of .coli_kv's 182 KB/token
- Budget the 64 GB explicitly: ~10-14 GB dense resident (int4) + ~2.5 GB page-cache reserve + slack leaves ~35-40 GB for the learned pin + LRU (~1800-2000 experts at ~19 MB); keep mlock ON (macOS default) and stay under ~54 GB RSS - the M5 report shows crossing into macOS memory compression is a double penalty (compressor CPU + SoC power stolen from the GPU)
- Use Accelerate/AMX for the dense resident GEMVs (attention projections, shared expert, lm_head): colibri deliberately uses no BLAS, but on M1 the AMX units are only reachable via Accelerate and deliver large GEMV gains at low power - offloading dense work there frees NEON cores for expert dequant-dot and I/O; M1 also lacks i8mm, so colibri's best int8 tile kernels don't exist on this chip, making AMX the bigger win
- Keep PILOT_REAL + PILOT_TWO router lookahead and re-measure recall on K3's router (K2-family sigmoid top-k routers should be similarly predictable to GLM's 71.6%); add the offline COUPLE pair-stats (.coli_pairs) which are free at runtime; with only 10 cores, cap PILOT_K at ~4-6 to avoid cache thrash
- Add a resident-preferring routing mode for speed (CACHE_ROUTE J=2 M=12 exists, colibri.c:2796-2879): on a 64 GB host streaming a 2.8T model, substituting rank 3..12 experts with resident ones cuts misses drastically; the built-in overlap/KL telemetry quantifies the quality cost - speed is priority #1 here, so this is a legitimate lever colibri ships but defaults off
- Use an external TB4/USB4 SSD (~3 GB/s) as a PARTIAL mirror via COLI_MODEL_MIRROR: the internal disk cannot hold two copies of a ~1.1 TB model, but the mirror validator accepts partial mirrors, so mirroring only the hottest shards adds ~40-50% aggregate read bandwidth with the deterministic hash split
- Repack K3's fused [E,...] stacked expert tensors at conversion time so each expert's gate/up/down are file-adjacent and 4 KiB-aligned (colibri gets its one-pread-per-expert miss cost from this layout); align slabs to 16 KiB for Metal newBufferWithBytesNoCopy
- Replace the pipe_wait sched_yield spin with the condvar path (COLI_PIPE_BLOCK=1) by default on macOS: with 10 cores the main-thread yield storm fights the OMP team during multi-ms cold reads; the ~5us condvar wake is noise against 0.5-3 ms expert reads (colibri.c:1892-1897)
- Consider running the batched expert SwiGLU on the M1 Max GPU (32-core, shares the 400 GB/s unified memory): colibri's moe_gemv hits 358-389 GB/s on M-series (backend_metal.mm:68-69), well above what 8 P-cores sustain via NEON, and the resident-experts-first submit ordering already overlaps GPU compute with miss preads
- Skip io_uring envy: on macOS the right async primitive stack is F_RDADVISE readahead from the PILOT thread + a small pread worker pool + F_NOCACHE for cold streams - exactly colibri's shape; invest instead in overlap quality (submit resident GPU work before miss I/O, next-block WILLNEED) which the code shows is where the wins came from
